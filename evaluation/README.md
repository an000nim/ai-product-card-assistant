# Проверка самопроверки модели

`cases.json` содержит один корректный фрагмент и четыре примера намеренных ошибок, связанных с исходными данными двух товаров. `run.py` передаёт каждый фрагмент вместе с зафиксированным входом из `fixtures/` в LLM-аудитор и сохраняет замечания. Файлы fixtures воспроизведены из сохранённых входов более раннего прогона; они могут отличаться от актуальных примеров в `examples/`. Запуск после выбора модели:

```sh
LLM_MODEL=qwen3:4b-instruct python3 evaluation/run.py > audit-observations.json
```

Непустой список замечаний не всегда означает, что модель нашла именно подставленную ошибку; комментарии необходимо читать. Модель может ошибочно оспорить верное утверждение или пропустить неправильное. Это небольшой диагностический набор, а не статистическая оценка качества, полноценный независимый аудит или замена сверки каждого утверждения человеком.

## Наблюдение на Qwen 3 4B Instruct

В сохранённом прогоне через OpenAI-совместимый API Ollama до перехода на режим ограниченного контекста `results/qwen3.json` модель указала именно на подставленную проблему во всех четырёх случаях с ошибками: материал чувствительного элемента, диапазон измеряемой среды, отрасль и разногласие по условию для реле. В контрольном примере с правильным трёхпроводным подключением модель также вернула замечание — оно относилось к дополнительной фразе «назначение прибора требует уточнения», хотя назначение приведено во входе. Это как минимум спорное срабатывание на сопутствующий текст, а не обнаружение ошибки в проверяемой схеме подключения.

Это пять вручную подобранных случаев и один запуск; по ним нельзя оценить вероятность галлюцинаций или доказать корректность проверки произвольного товара. Ответы на реальные карточки также требуют просмотра человеком. Результаты доступны целиком, чтобы было видно, что именно модель написала.
