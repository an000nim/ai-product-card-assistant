# AI-помощник для черновика карточки КИП

**Прототип проверен на двух товарах с локальной Qwen 3 4B Instruct.** Сохранённые результаты: [регулятор](../examples/results/trm151.json) и [датчик](../examples/results/dts014.json). Проверка требований — [ACCEPTANCE.md](../ACCEPTANCE.md), сверка содержания — [REVIEW.md](../REVIEW.md).

Локальный прототип на Python: принимает JSON товара, обращается к локальному API Ollama или совместимому с OpenAI Chat Completions API, формирует JSON с SEO-заголовком, описанием, поисковыми фразами и коммерческим блоком. Для проверки отдельно возвращает исходные характеристики, пропущенные поля, возможные источники утверждений и предупреждения.

**Результат всегда является черновиком для проверки человеком.** Поиск совпадающих чисел, слов и знаков не проверяет смысл технического утверждения, единицы измерения, логические связи, достоверность входа или применимость значений серии к конкретной модификации. Нельзя использовать результат для технического решения или публикации без проверки паспорта прибора.

## Запуск

Нужен Python 3.9+ и запущенная Ollama. Сторонние Python-зависимости не требуются. Скачайте Ollama с https://ollama.com/ и загрузите модель:

```sh
ollama pull qwen3:4b-instruct
```

В папке проекта:

```sh
python3 app.py examples/trm151.json > result-trm151.json
python3 app.py examples/dts014.json > result-dts014.json
```

Локальная модель может генерировать ответы несколько минут, особенно на компьютере с 8 ГБ памяти. Ранний прогон через OpenAI-совместимый API завис при высокой нагрузке на память. После перехода на прямой API Ollama с контекстом 3072 токена оба примера завершились. Скорость и достаточность памяти на другом компьютере не гарантированы. По умолчанию используется локальный API Ollama на `http://127.0.0.1:11434/api/chat`; интернет для генерации не нужен после загрузки модели. Для другого сервиса установите `LLM_BACKEND=openai`, `LLM_MODEL`, `LLM_BASE_URL` и при необходимости `LLM_API_KEY` в окружении. Ключ в коде не хранится; `.env` исключён из репозитория. Конкретный API должен поддерживать Chat Completions и `response_format: json_object`. Параметр `LLM_MAX_ATTEMPTS` задаёт 1–3 попытки генерации (по умолчанию 2).

Для компьютеров с ограниченной памятью есть режим прямого API Ollama: он ограничивает контекст и просит выгрузить модель после каждого ответа. Например:

```sh
LLM_BACKEND=ollama LLM_MODEL=qwen3:4b-instruct OLLAMA_CONTEXT_SIZE=3072 python3 app.py examples/trm151.json > result.json
```

`OLLAMA_BASE_URL` по умолчанию равен `http://127.0.0.1:11434`; допустимый контекст — от 2048 до 8192 токенов. Слишком маленький контекст может ухудшить ответ или привести к потере части данных; его следует подбирать и проверять на конкретной модели. Режим `LLM_BACKEND=ollama` включён по умолчанию; `LLM_BACKEND=openai` поддерживает совместимый Chat Completions API. Выгрузка после каждого запроса снижает удержание памяти между запросами, но не гарантирует, что при самой генерации памяти хватит; повторная загрузка замедляет работу.

Одна попытка генерирует все четыре текстовых поля. Затем выполняется отдельная самопроверка той же моделью; её замечания используются как дополнительная эвристика и могут содержать ошибки или пропускать их. При нарушении длины, неподтверждённых числах, точных повторах или отдельных других признаках риска программа повторяет запрос с предыдущим ответом и причинами. Неверный формат ответа модели также может вызвать повтор. Из полученных вариантов выбирается вариант с меньшим числом эвристических признаков риска, повторов и нарушений длины. Это не гарантия фактической правильности. После последней попытки результат возвращается вместе с предупреждениями; он **не считается автоматически проверенным**. Если последняя попытка вернула неверный формат, но ранее был получен черновик, сохраняется предыдущий вариант с указанием ошибки. При ошибке сети, неправильном JSON модели или входного файла команда завершится с ненулевым кодом и сообщением в stderr.

## Вход

JSON-объект `name` обязателен; `model`, `manufacturer`, `description` — строки; `specs` — объект с названиями и значениями характеристик. Неизвестное значение передавайте пустой строкой. Необязательные `sources` — массив объектов `title` и `url`; `conflicts` — список строк с описанием противоречий. Ссылки и конфликты включаются в итог для менеджера; автоматического скачивания источников и проверки их актуальности нет.

Необязательный `profile` принимает значения `pressure_gauge`, `temperature_sensor`, `temperature_controller` или `other`. При отсутствии программа пытается определить профиль по названию. Встроенные списки базовых полей — неполные эвристики, а не стандарт на все модификации. Поле считается заполненным, если его название совпало с одним из вариантов и значение непустое. Если тип не распознан, программа сообщает, что полноту нужно проверить вручную. Подробные входные примеры — в `examples/`.

## Результат и проверка

- `title`, `description`, `queries`, `commercial` — текст, написанный моделью и затем обработанный программой. Если она не включила точный код модели во вступление или другое место описания, код добавляется программой из поля `model`; это отмечается в `review`. Если короткое описание не называет явно пустую характеристику, программа может добавить предложение о том, что её требуется уточнить; такая добавка также отмечается в `review`. Точные повторные предложения могут удаляться, а в короткое описание могут добавляться дословные характеристики из входа. Для некоторых численных характеристик, явно помеченных как данные серии, программа может добавить эту оговорку к соответствующему предложению. Для одной распознанной ситуации программа может убрать слишком широкое утверждение об агрессивной среде, если вход содержит более узкое условие совместимости материалов. Это частная эвристика, а не универсальная проверка смысла. Перечни удалений, добавлений и оговорок сохраняются в `review`, первоначальный ответ — в `raw_generation`. Даже с оговоркой предложение необходимо проверить по смыслу.
- `characteristics` — исходные значения `specs`, пустые помечены «данных нет». Модель не меняет этот список.
- `missing_fields` — незаполненные исходные поля, обнаруженные базовые пробелы и вручную внесённые противоречия источников.
- `review.local_request_metrics` — число токенов в запросе и ответе локальной модели; `near_context_limit` предупреждает о запросе, близком к размеру контекста. Показатель не доказывает отсутствие усечения, особенно при длинных ответах или повторных запросах.
- `review.automated_issues` — нарушения длины и формата, неподтверждённые числа и сочетания числа с единицей, некоторые неподтверждённые знаки, признаки возможного смешения параметров серии, замечания самопроверки модели и ошибки самой самопроверки.
- `claim_trace` — фрагменты текста с кандидатами исходных полей, подобранными по общим словам. Это ориентир, а не подтверждённые цитаты. Каждый фрагмент помечен для ручной проверки; номера без совпадения в исходных данных показаны отдельно.
- `source_facts`, `source_conflicts`, `sources` позволяют сопоставить черновик с входом и первоисточниками. Программа не превращает конфликтующие значения в установленную характеристику.

Числовая проверка эвристическая: совпадение цифр с любым исходным полем не доказывает корректность единицы, знака, интервала или связи чисел со свойствами; самопроверка той же моделью не является независимым доказательством; возможны как пропущенные ошибки, так и ложные предупреждения. Проверка знаков и оговорок тоже неполна. Модель может опустить ограничение, ошибиться без новых чисел или придумать назначение. Следует проверять **каждое** утверждение, в том числе при пустом списке автоматических предупреждений. Не заполняйте вход вредоносными инструкциями; промпт просит модель трактовать их как данные, но это не абсолютная защита.

Если исходных фактов недостаточно, соблюдение 800–1200 символов без выдумок может быть невозможно. В этом случае приложение выдаёт предупреждение, а не заявляет, что длина соблюдена. Сама модель может делать повторы и не соблюдать формат; качество нужно оценивать отдельно.

## Примеры и источники

Файлы `examples/results/` — реальные результаты локального запуска Qwen 3 4B Instruct 04.11.2026 через API Ollama, контекст 3072. Для каждого товара потребовалась одна попытка генерации и один запрос самопроверки. Тексты вручную не редактировались. У регулятора программа сократила длинный заголовок по границе фразы; у датчика добавила оговорку «по данным серии» в коммерческий блок. Всё это зафиксировано в `review`, исходные четыре поля модели сохранены в `raw_generation`.

| Пример | Заголовок, символов | Описание, символов с пробелами | Поисковые фразы |
|---|---:|---:|---:|
| ТРМ151 | 37 | 904 | 5 |
| ДТС014 | 48 | 1003 | 5 |

После реального прогона добавлены проверки некорректного ввода и формата ответа API. Обработка сохранённых реальных ответов повторно проверена текущим кодом в тестах воспроизведения; это не новый запрос к модели. Оба примера проходят `evaluation/check_examples.py`. Автоматических замечаний в них нет, но это не доказательство отсутствия смысловых ошибок. Подробная сверка ассистентом записана в REVIEW.

`evaluation/observations/` содержит более ранние ответы и снимки входов для анализа ошибок; они не являются итоговыми примерами. Исходные товары найдены в каталоге работодателя, записи 54422 и 54527.
- ТРМ151-Щ1.РР.01: [карточка продавца](https://www.souz-pribor.ru/product/trm151-shch1-rr-01/), [руководство ОВЕН ТРМ151-01](https://owen.ru/downloads/re_trm151-01.pdf). Предельная нагрузка реле оставлена незаполненной из-за расхождения в знаке условия cos φ; перед публикацией нужен паспорт конкретного экземпляра. Вход уточняет, что два последних шага последней программы зарезервированы для СТОП и АВАРИЯ.
- ДТС014-50М.В3.25/0,2: [расшифровка обозначений ОВЕН](https://owen.ru/product/dtshh4_termosoprotivleniya_s_kabel_nim_vivodom/modifications), [характеристики серии](https://www.souz-pribor.ru/product/dts014/). В3 обозначает класс допуска В и трёхпроводное соединение; параметры из таблицы серии помечены как такие и требуют сверки с паспортом изделия.

Входные JSON составлены по исходным источникам вручную; их необходимо перепроверять при изменении документов. Цена и наличие намеренно исключены.

## Проверка

```sh
python3 -m unittest discover -s tests -v
python3 evaluation/check_examples.py
```

Тесты проверяют валидацию, самопроверку модели, устранение точных повторов и добавление исходных характеристик, недостающие поля, повторы, ошибки API и JSON модели, повторные попытки, неподтверждённые числа, знаки и некоторые опасные формулировки про параметры серии и рекламные оценки и выбор из нескольких ответов. Они не доказывают отсутствие всех смысловых ошибок LLM. Дальнейшие улучшения: отдельная проверка каждого утверждения по точным цитатам, набор тестовых примеров с экспертной разметкой, отказ от публикации до ручной проверки, более надёжная модель и профили товаров с согласованными обязательными полями.


## Промпты и решения

`SYSTEM_PROMPT` в `app.py` задаёт роль редактора B2B-каталога, четыре текстовых поля, длину и ограничения по фактам. Данные отделены от инструкции отдельным сообщением. `AUDIT_PROMPT` просит ту же модель найти неподтверждённые утверждения; это дополнительный сигнал, не независимая экспертиза. Повторная генерация получает предыдущий вариант и конкретные замечания. Число попыток ограничено, бесконечных повторов нет.

Структурированные характеристики копируются из входа без генерации. Неизвестные значения остаются неизвестными. Прямой API Ollama выбран для ограничения памяти на тестовом компьютере. Веб-интерфейс, БД и деплой не реализованы: ТЗ допускает JSON и локальный прототип.

## Ошибки и диагностика

- При успехе stdout содержит JSON, код завершения — 0. Наличие JSON не означает готовность к публикации: читайте `review` и `missing_fields`.
- При некорректном файле/JSON, повторяющихся ключах, неверных типах, недоступном API или отсутствии пригодного ответа код завершения — 1, сообщение находится в stderr. При сбое дополнительной самопроверки черновик может быть сохранён с предупреждением.
- Если Ollama не отвечает, откройте приложение Ollama или запустите `ollama serve`; проверьте `ollama list` и наличие `qwen3:4b-instruct`. Если модель не установлена, выполните команду загрузки выше.
- Тайм-аут одного API-запроса — 600 секунд. Одна попытка включает два запроса; при двух попытках ожидание может быть длительным. Не запускайте несколько генераций одновременно на компьютере с малым объёмом памяти.
- При нехватке данных приложение возвращает короткий черновик с предупреждением о длине, а не дополняет его выдуманными характеристиками. Отсутствующие поля перечислены отдельно.
- Для локального режима API-ключ и платные сервисы не нужны. Совместимость с внешним API проверялась тестами с подменой ответа, реального платного запроса не выполнялось.

## Состав проекта

`app.py` — CLI и обработка; `examples/` — два входа и результата; `tests/` — 66 автоматических тестов; `evaluation/` — диагностика и проверка примеров; `REVIEW.md` — сверка содержания; `ACCEPTANCE.md` — соответствие ТЗ; `SUBMISSION.md` — заготовка сопроводительного сообщения. Сторонних Python-зависимостей нет, поэтому установка через pip не требуется. Проверено на Python 3.12; код использует стандартную библиотеку и синтаксис Python 3.9+.
